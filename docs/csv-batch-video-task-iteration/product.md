# 批量视频任务产品方案

## 1. 产品目标

当前系统已经具备单条视频任务的执行能力，本轮需要补齐面向客户交付的批量入口。

这一轮的目标是提供一个客户能理解、能批量提交、能回看结果的标准产品流程。

最终产品目标：

- 客户下载标准 Excel 模板
- 客户在 Excel 中填写任务、放入素材、编写 prompt
- 客户回到 `/batch` 上传 Excel
- 系统完成解析、校验、确认
- 后端异步执行整批任务
- 用户在任务列表中持续看到进度、状态和结果

## 2. 页面形态

`/batch` 页面只保留两个功能区：

### 2.1 任务列表

任务列表用于展示历史批量任务和当前运行中的任务。

列表字段建议固定为：

- 任务名称
- 创建时间
- 总任务数
- 成功数
- 失败数
- 运行中数
- 进度百分比
- 当前状态

点击任务后，右侧或下方展开任务详情。

详情中展示：

- 每一行任务的状态
- 每一行任务的结果链接
- 每一行任务的错误信息
- 必要的行级原始信息回查

### 2.2 创建批量任务

创建批量任务的交互非常简单，只包含：

- 下载 Excel 模板
- 上传 Excel 文件
- 显示解析结果与校验结果
- 点击确认开始执行

模型和参数选择都在 Excel 模板里完成。

## 3. 用户流程

### 3.1 下载模板

用户从 `/batch` 下载系统当前版本对应的 Excel 模板。

模板中已经包含：

- 固定列结构
- 模型可选项
- 参数可选项
- 填写说明

### 3.2 填写模板

用户在 Excel 中完成：

- 任务类型选择
- 模型选择
- 时长选择
- 横竖版选择
- prompt 填写
- 图片和视频素材填充

### 3.3 上传并校验

用户在 `/batch` 上传 Excel 后，系统返回：

- 表头是否合法
- 每一行是否可执行
- 哪些行有错误
- 哪些槽位引用不合法

此时还未真正执行任务。

### 3.4 用户确认后异步执行

只有用户点击“确认开始执行”后，系统才创建批量任务并异步执行。

执行过程完全在后端完成，不依赖页面常驻。

### 3.5 回看结果

任务一旦创建成功，即使用户关闭页面，稍后再打开 `/batch` 仍可继续查看：

- 整批任务进度
- 当前状态
- 行级结果
- 行级失败原因

## 4. 页面原则

### 4.1 保持简单

页面只需要帮助用户完成：

- 上传
- 校验
- 确认
- 查看结果

### 4.2 复杂度前置到模板

模型、参数、素材槽位、prompt 占位符约定统一放在 Excel 模板中。

这样页面可以保持稳定，模板可以迭代。

### 4.3 执行逻辑后置到后端

用户只负责提交任务，不负责驱动执行过程。

后端负责：

- 排队
- 调度
- 重试
- 状态回写

## 5. 第一阶段范围

第一阶段只做最小可用闭环：

- 下载 Excel 模板
- 上传 Excel
- 解析与校验
- 创建批量任务
- 后端异步执行
- 查看任务列表和任务详情

第一阶段不追求：

- 在线编辑模板
- 在 `/batch` 页面直接配置模型参数
- 复杂筛选器和高级报表
- Excel 在线预览媒体

## 6. 结论

从产品视角看，这个需求的正确形态非常清楚：

- 页面足够简单
- Excel 承担任务描述
- 后端承担异步执行
- 列表承担结果回看

也就是说，`/batch` 的本质是一个批量任务管理页。
