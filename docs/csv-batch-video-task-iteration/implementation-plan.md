# 批量视频任务实施计划

## 1. 实施原则

实施按下面顺序推进：

1. 先把产品形态钉死
2. 再把 Excel 模板协议钉死
3. 再做后端解析和执行
4. 最后只给前端保留最小页面

## 2. 第一阶段交付目标

第一阶段只交付一个最小闭环：

- 下载 Excel 模板
- 上传 Excel
- 解析与校验
- 用户确认
- 创建异步批量任务
- 任务列表查看进度
- 任务详情查看行级状态和结果

## 3. 分阶段任务

### 3.1 阶段 A：模板协议定稿

目标：

- 固化 `Tasks` 表结构
- 固化固定素材槽位
- 固化 prompt 占位符语法
- 固化模型和参数列
- 固化模板版本号机制

交付：

- 一份正式 Excel 模板定义
- 一份模板示例

### 3.2 阶段 B：后端解析层

目标：

- 新增 `.xlsx` 解析能力
- 读取 `Tasks` sheet
- 识别行级媒体槽位
- 输出标准化任务结构

交付：

- `POST /api/batch/excel/parse`

### 3.3 阶段 C：后端校验层

目标：

- 校验字段完整性
- 校验任务类型
- 校验模型与参数组合
- 校验 prompt 占位符引用
- 返回行级错误与警告

交付：

- 解析与校验统一返回体

### 3.4 阶段 D：批量任务持久化与执行

目标：

- 新增 `BatchJob`
- 新增 `BatchJobItem`
- 接入后台执行器
- 复用统一生成主链路
- 回写状态和结果

交付：

- `POST /api/batch/jobs`
- `GET /api/batch/jobs`
- `GET /api/batch/jobs/{job_id}`

### 3.5 阶段 E：前端最小页面

目标：

- `/batch` 只显示任务列表
- 提供“创建批量任务”入口
- 上传 Excel 并展示预校验结果
- 用户确认后创建任务
- 查看任务详情

交付：

- 一个真正简单的批量任务页

## 4. 页面交付要求

`/batch` 页面按下面结构交付：

- 任务列表
- 上传 Excel
- 预校验结果
- 确认执行
- 任务详情

## 5. 风险点

### 5.1 风险：Excel 媒体承载复杂

说明：

- 纯文本本地路径不可行
- 本地文件必须真正跟 workbook 一起提交

控制：

- 先把模板承载规则写死
- 先明确第一阶段只支持哪些媒体嵌入方式

### 5.2 风险：模板和后端协议漂移

说明：

- 如果模板一套、后端一套，就会不断返工

控制：

- 模板协议单点定义
- 后端解析只围绕模板协议实现

### 5.3 风险：页面范围扩张

控制：

- 页面范围严格受限
- 参数全部沉到 Excel 模板

## 6. 验收标准

第一阶段的验收标准只看下面几点：

- 用户能下载 Excel 模板
- 用户能上传 Excel
- 用户能看到清晰的预校验结果
- 用户确认后任务能异步执行
- 页面关闭后重新打开仍能看到任务状态
- 每一行都能看到成功结果或失败原因

第一阶段暂不纳入验收范围的能力：

- 在线编辑 Excel
- 页面上选模型
- 高级筛选报表
- 多轮重试策略

## 7. 本轮结论

本轮交付聚焦于一条清晰主线：

- Excel 负责描述任务
- 页面负责上传和查看
- 后端负责异步执行
